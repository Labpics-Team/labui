# Участие в Lab UI

Изменение должно улучшать наблюдаемое поведение компонента, его подключение
или документацию и сохранять [инварианты системы](docs/reference/invariants.md).
Для ошибки приложите воспроизведение и ожидаемый результат; для возможности
опишите пользовательский сценарий. Обычные вопросы и предложения принимаются
в [Issues](https://github.com/Labpics-Team/labui/issues).

## Подготовить окружение

Следуйте [первому запуску каталога](docs/tutorials/catalogue.md).
Изменяйте исходники в отдельной ветке; сохраняйте закреплённый lockfile.

## Выбрать место изменения

- Поведение, состояния и общие типы компонента — `packages/core`.
- Представление в конкретном фреймворке — его пакет привязки.
- Общие генерируемые части привязок — `packages/adapter-codegen`.
- Цветовые роли, геометрия и материал — соответствующие пакеты из [карты](docs/reference/packages.md).
- Примеры и браузерные проверки — `apps/docs`.

Цвет вычисляет LabColors, движение исполняет LabMotion. Изменение их
внутреннего механизма выполняется в репозитории владельца.
Figma служит эталоном для чтения; используйте только публичную Community-ссылку.
Приватные Figma identifiers, токены доступа и локальные секреты не включаются
в код, fixtures, логи или описание PR.

## Проверить изменение

Из корня workspace доступны:

```sh
pnpm build
pnpm typecheck
pnpm test
pnpm check
pnpm test:e2e
```

Выбирайте адресные проверки по изменённому поведению. `pnpm test` проверяет
пакеты по очереди и сохраняет ошибку общего запуска, если один из них отказал.
`pnpm check` запускает Biome. Браузерные сценарии требуют установленных
браузеров Playwright; их состав задан в
[конфигурации](apps/docs/playwright.config.ts).

Для свойства Core добавьте `*.test.ts` в [packages/core/test](packages/core/test/).
Назовите в `describe` компонент или контракт, а в `it` — условие и видимый результат.
Например, следующая команда из корня проверяет применение шрифта к области темы.

```sh
pnpm --filter @labpics/ui-core test test/theme-font.test.ts -t 'применяет font-family'
```

В итоговой строке Vitest появится `1 passed`. Для всего файла уберите `-t` с его
аргументом. Файлы выбирает [конфигурация Vitest пакета](packages/core/vitest.config.ts).

Для взаимодействия в браузере добавьте `*.spec.ts` в [apps/docs/tests](apps/docs/tests/).
После сборки workspace установите Chromium и проверьте, что клавиша пробела
переключает флажок в фокусе.

```sh
pnpm --filter @labpics/ui-docs exec playwright install chromium
pnpm --filter @labpics/ui-docs exec playwright test --project=chromium tests/checkbox.spec.ts --grep 'Space on the focused box'
```

Playwright покажет имя проекта, сценарий и результат. Проверки файлов самого
каталога используют `node:test` и суффикс `.test.mjs` в том же каталоге.
Их запускает `pnpm --filter @labpics/ui-docs test`. Контракты потребителя
Icons с именами `icons-*` и `prepare-icons-inputs*` запускает
[проверка установленного пакета](.github/workflows/icons-consumer.yml).

Во вкладке Checks вашего PR шаг `Unit tests` задания `lint · typecheck · build`
показывает результаты пакетов. Сценарий с клавишей пробела входит в
`playwright smoke (critical path)` того же [CI](.github/workflows/ci.yml).
[Полный браузерный прогон](.github/workflows/e2e-full.yml) находит все `*.spec.ts`
и запускается по расписанию или вручную.
Lab UI, LabColors, LabMotion и LabIcons публичны и используют стандартные
GitHub-hosted runners. Linux-задачи запускаются на `ubuntu-latest`,
платформенные проверки — на соответствующих Windows и macOS runners.
Для изменения поведения добавьте проверку, отличающую исходную ошибку
от допустимого соседнего случая. Для визуального изменения сравните
реальный рендер с эталоном.

## Передать изменение

Откройте PR с результатом для пользователя, относящимися проверками
и оставшимися ограничениями. Если меняется публикуемый пакет, оформите
изменение версии через [Changesets](.changeset/) командой `pnpm changeset`.

Fork PR проходит те же проверки на GitHub-hosted runners с правами чтения
репозитория; для первого внешнего запуска GitHub может запросить approval
сопровождающего.

Сообщения об уязвимостях передавайте через [приватный канал](SECURITY.md).
