# Серверный HTML и гидратация

Серверные входы `@labpics/ui-vue/ssr`, `@labpics/ui-svelte/ssr`,
`@labpics/ui-solid/ssr` и `@labpics/ui-astro/ssr` возвращают HTML компонента
со стилями и Declarative Shadow DOM. Включайте эту строку в серверный ответ.
Обычная клиентская вставка через `innerHTML` не создаёт declarative shadow root.
Тему и шрифты подключает приложение.

Для серверных `/ssr`-входов установите `@lit-labs/ssr`. Плагину гидратации ядра
также нужен `@lit-labs/ssr-client`; адаптер Astro подключает его сам.
Совместимые версии указаны в `peerDependencies` пакета `@labpics/ui-core`.

## Astro

Добавьте интеграцию в конфигурацию приложения:

```ts
import { defineConfig } from 'astro/config';
import hydrate from '@labpics/ui-astro/hydrate';

export default defineConfig({
  integrations: [hydrate()],
});
```

Затем используйте обёртки компонентов:

```astro
---
import Switch from '@labpics/ui-astro/Switch.astro';
---
<Switch checked={false} defaultChecked={true}>Уведомления</Switch>
```

Интеграция обеспечивает загрузку официальной поддержки гидратации до LitElement
в клиентской сборке и на dev-сервере. Она нужна и когда другие страницы приложения
используют Web Components напрямую. Без интеграции обёртка сообщает об ошибке.
При переходе с прежних обёрток добавьте этот вызов в `integrations`.

## Vite и другие серверные приложения

В приложении на Vite подключите тот же механизм через ядро:

```ts
import { defineConfig } from 'vite';
import hydrate from '@labpics/ui-core/hydrate';

export default defineConfig({
  plugins: [hydrate()],
});
```

Загружайте используемые компоненты через `@labpics/ui-core/<имя>` или клиентский
адаптер. Например, `renderSwitch`
из `@labpics/ui-vue/ssr` рендерит серверную часть, а
`@labpics/ui-core/switch` регистрирует её в браузере.

Для других сборщиков соблюдайте [порядок загрузки Lit SSR](https://lit.dev/docs/ssr/client-usage/):
поддержка гидратации должна исполниться до LitElement. Первый `import` в исходном
файле сам по себе не гарантирует этот порядок после разделения сборки на чанки.
Проверяйте итоговую сборку приложения.

Подключение только клиентских компонентов не требует плагина гидратации.
Серверный HTML и клиентские ресурсы должны быть собраны из одной версии ядра.

Switch передаёт подписи и имя input до hydration. Независимая видимость сторон
и `ariaLabel` для переключателя без текста описаны в [справке подписей](reference/switch-labels.md).

## Значения Boolean

Явный `false` сохраняется, в том числе вместе с `defaultChecked: true`.
Отсутствующий проп или `undefined` оставляет значение компоненту. В клиентских
адаптерах Vue, Solid и Svelte удаление пропа также не сбрасывает текущее значение.
Начальные `defaultChecked` и `defaultIndeterminate` применяются один раз.

Серверный рендерер сохраняет итоговые публичные Boolean в служебном атрибуте.
Ядро проверяет весь снимок и восстанавливает значения перед первым обновлением.
Присваивания JS-свойств до регистрации компонента и после восстановления снимка
имеют приоритет; повторное подключение элемента не возвращает серверное состояние.
Для изменения начального состояния в браузере задавайте JS-свойство. Правки
обычных атрибутов до регистрации не заменяют снимок серверного состояния.

Служебный атрибут нельзя создавать или изменять вручную. Неверный формат,
неизвестное свойство или повторное применение сообщаются как ошибка.
У собственных Boolean-свойств экземпляра должен сохраняться `configurable: true`;
неподходящий дескриптор вызывает `TypeError`. Это условие не относится к
accessor-свойствам на прототипе. Обычные поля класса и объявления свойств Lit
соответствуют этому условию.
Перенос относится к объявленным публичным Boolean; объекты и массивы требуют
собственной передачи через контракт приложения. Обычный серверный рендеринг
самого Vue, Solid или Svelte не равнозначен этим отдельным `/ssr`-входам.
