# ADR-0009. Acrylic v2: luminosity-конвейер, коридор выводом, файлы-материалов

Статус: **реализовано** (2026-07-09, ветка acrylic-v2 поверх ADR-0008).
Продолжает ADR-0004 (рецепт Acrylic, коридорная гарантия) и ADR-0008 (материалов
три). Вкусовой мандат владельца: «правильный акрил по мотивам Fluent,
одноуровневый (как темы) с Liquid Glass, оптимизация до физического порога,
структуру материалов интуитивнее»; смесь — luminosity (вердикт владельца по
интерактивному демо трёх рецептов); `glass` НЕ переименовывается.

## Контекст

ADR-0004 приземлил acrylic с задекларированным разменом: тинт straight-alpha
БЕЗ Fluent-смеси — и честно зафиксировал следствие: acrylic отличался от glass
только зерном («тот же фрост, но дороже» — формулировка ADR-0008). Официальный
рецепт Fluent (Microsoft Learn, Acrylic material): *background → blur →
exclusion blend → color/tint overlay → noise*; современный WinUI добавляет
luminosity-слой (`AcrylicBrush.TintLuminosityOpacity`) — зажим яркости
подложки, дающий акрилу его «молочную» стабильность.

**Факт браузера (пиксельная проба, Chromium 149, 2026-07-09; память
css-backdrop-blend-facts):**

1. CSS-слоёный путь НЕВОЗМОЖЕН: `mix-blend-mode` ребёнка не достаёт до
   backdrop-фона — backdrop-filter создаёт stacking context, смесь видит
   только слои родителя (плоский результат на любом фоне, с изоляцией и без).
2. РАБОТАЕТ единственный путь: SVG-цепочка ПО `url(#f)` внутри самого
   backdrop-filter (легальный синтаксис Filter Effects L2). Chromium рендерит;
   Safari/Firefox парсят, но не рендерят на backdrop — тот же расклад, что у
   рефракции LG (ADR-0003), и тот же гейт.

## Решение 1 — рецепт v2: конвейер внутри фильтра

`engine/acrylic.ts` (монтируется существующим `mountMaterialRuntime()`):
пять статичных tier-фильтров в скрытом `<svg>` —

```
backdrop-filter: url(#lab-acrylic-<tier>)
  feGaussianBlur(48)                      ← ступень --_blur-live (Решение 3)
  → feColorMatrix saturate(1.8)           ← --_saturate-on (существующая)
  → feFlood(var(--lab-bg-material-<tier>-01), flood-opacity Λ)
  → feBlend mode="luminosity"             ← недостающий слой Fluent
```

- **Один проход композитора, ноль JS в кадре**: JS пишет инлайн-пару
  backdrop-filter только на attach/detach (паттерн LG). Перф-замер:
  медианный кадр под движущимся контентом = **16.70ms у solid, glass и
  acrylic одинаково** (полный 60fps-бюджет; bench/BASELINE.md) — это и есть
  физический порог.
- **Ноль собственного цвета**: flood-color — живой `var()` контрактного тинта
  (CSS-свойство на feFlood); тема и поезд colors перекрашивают фильтр без JS
  (доказано e2e: флип темы без ре-маунта).
- **Пространство счёта закреплено**: `color-interpolation-filters="sRGB"` — то
  же гамма-пространство, что у CSS-смесей и compositeOver-стека (SVG-дефолт
  linearRGB дал бы другие байты — факт пробы).
- **Сила зажима ДЕРИВИРУЕТСЯ**: αf = альфа тинт-токена × Λ. Прозрачный tier
  зажимает слабее сам собой — ноль новых значений на tier.
- **Λ = 0.7** — аналог `TintLuminosityOpacity`. PROVENANCE: DECLARED-размен
  `kind: declared-tradeoff`, визуально откалибровано владельцем на демо трёх
  рецептов (2026-07-09); замок значения — acrylic-engine-contract.test +
  голден пар. Рычаг: рост Λ сужает коридор (Решение 2).
- **Exclusion-слой legacy-рецепта НЕ поставляется**: современный WinUI ушёл на
  luminosity; на демо владелец выбрал luminosity. Возврат exclusion возможен
  тем же конвейером (feBlend mode="exclusion") — дверь дешёвая, не открываем
  без нужды.
- **Гейт** = `supportsRefraction()` (url()-фильтр, реально рисующий на
  backdrop, Chromium) — требование идентично рефракции, проба одна.
- **Честные деградации**: инлайн движка сильнее листовых `@media`, поэтому
  движок гаснет САМ под `prefers-reduced-transparency` / `forced-colors` /
  `prefers-contrast: more` (runtime-скан + change-листенеры; паритет списка
  лист↔движок — замок в тестах). Известный зазор: инлайн LG-линзы переживает
  forced-colors — pre-existing, вынесен в follow-up, здесь закрыт с рождения.

## Решение 2 — коридор гарантии ВЫВОДОМ (закрытие долга «C»)

ADR-0004 оставил множитель сжатия коридора `C` «требующим измерения». v2
закрывает долг сильнее — выводом из формулы смеси (`src/acrylic-corridor.ts`):

Пиксель после смеси: `C' = αf·Q + (1−αf)·Cb`, где `Q = ClipColor(SetLum(Cb,
Lf))` — цвет с blend-лумой ровно `Lf` (лума flood-тинта). Канал любого цвета
с лумой Lf зажат в `[q_lo, q_hi]` (вся лума на канале / остальные каналы в 1),
поэтому бокс `[αf·q_lo, αf·q_hi + (1−αf)]` по каждому каналу — **внешняя**
граница достижимого: гарантия может только недообещать, никогда пере-.
Blur — выпуклое усреднение, saturate клампится в куб: посылка держится для
всего конвейера.

Этот бокс подаётся в СУЩЕСТВУЮЩИЙ `evaluateTier(…, {backdrop})` (ADR-0004
Решение 2 ровно для этого параметризовал гарантию). Результат на живом
контракте (голден `acrylic-corridor.test.ts`):

| пара | glass worst | acrylic v2 worst | вердикт |
|---|---:|---:|---|
| light/soft | 4.059 | **4.753** | **становится guaranteed** |
| dark/subtle | 3.577 | **5.320** | **становится guaranteed** |
| остальные 8 | — | строго ≥ glass | 6 guaranteed / 2 честно нет |

Итого **8/10 guaranteed** (было 6/10), ни одна пара не ухудшена. Честное
ограничение бокса: он несёт только пер-канальные следствия лумы (без связки
каналов); на крайне-светлых/тёмных флудах (наши нейтральные тинты) сжатие
сильное, на средней луме бокс деградирует к широкому — К КОНСЕРВАТИВНОМУ.
Замки: property 20k сэмплов (точная W3C-симуляция ⊂ бокс), SetLum-инвариант,
монотонность по αf, интеграция «зажим не ухудшает ни один вердикт»,
браузерный дифференциал (ниже).

## Решение 3 — одна ступень размытия для живых материалов

Вопрос владельца: какие радиусы, «чтобы выглядело одноуровнево, поумнее чем
frost=blur». Ответ: **одноуровневость — закон структуры, не совпадение чисел**:
glass и acrylic делят ОДНУ ступень лестницы Figma BG-blur (Base 48px) ОДНИМ
токеном `--_blur-live` (бывший `--_blur-glass`); различие материалов —
анатомия (линза / зажим+зерно), не сила фроста.

Почему зажим не требует компенсации радиуса (частотный вывод): luminosity-слой
режет НИЗКОчастотный размах яркости (диапазон полосы), а видимость деталей
сквозь материал определяется остаточной ВЫСОКОчастотной энергией, которую
гаусс σ=48 уже давит на порядки. Формально: уравнивание остаточной яркостной
энергии на пике контрастной чувствительности (f₀ ≈ 0.24 цикл/px при 96dpi)
даёт поправку σ′² = σ² − ln(1/(1−Λ))/(2π²f₀²) ≈ 2304 − 1.06 px² → Δσ ≈
0.01px — неизмеримо. Хрома-каналы зажим не трогает вовсе (у обоих материалов
одинаковы). Значит равный радиус = равный уровень, компенсация не нужна.

## Решение 4 — файлы-материалы (находимость)

Жалоба владельца: «не могу найти акрил в репо». Исходник разрезан на
`src/materials/{base,glass,acrylic,engine-held,solid,degradations,veil}.css` —
материал находится по имени файла; README пакета открыт таблицей материалов.
Поставка НЕ меняется: один `dist/material.css`, склеенный по закону порядка
`src/materials/order.ts` (порядок = каскад; solid после мод, деградации после
всего). Одна функция склейки (`scripts/material-css.ts`) на билд и на все
CSS-тесты — вторых копий нет. Замок закона — `material-css-order.test.ts`.

## Решение 5 — зерно per-device-pixel

Генератор эмитит ДВА объявления одного ассета: `url()` (фолбэк) +
`image-set(uri 1x, uri 2x, uri 3x)` под `@supports`. На DPR≥2 браузер берёт
плотную запись → интринзик-тайл 24/16 CSS-px → зерно остаётся в один
ФИЗИЧЕСКИЙ пиксель (как у Fluent) без новых ассетов (дубль строки гасится
gzip). `@supports` обязателен: невалидное значение уронило бы всю multi-bg
декларацию (включая тинт). Замок — печать image-set в acrylic-noise.test.

## Тесты (классы Фаулера)

- **А**: аналитические якоря коридора; кросс-файловые замки движок↔лист↔Λ
  (acrylic-engine-contract); контракт склейки.
- **Б**: голден пар worst-контрастов (замок против дрейфа контракта и Λ);
  печати генератора; замок закона порядка; существующие деградации расширены.
- **В**: property 20k+2k (симуляция ⊂ бокс; SetLum-инвариант); браузерный
  дифференциал `acrylic-live.spec.ts` (в SMOKE): пиксели композитора внутри
  выведенной полосы, зажим строго уже фолбэка (A/B на одной странице),
  **канальный детектор режима** на насыщенном синем поле.
- **Д (диверсия, RED-proof)**: мутант `mode="normal"` — детектор режима упал
  (пиксель лёг в 1.6 байта к симуляции normal); честный luminosity — сошёлся
  (Δ3.9 байта). Урок класса: яркостный дифференциал СЛЕП к подмене режима —
  режим ловится только каналами над цветным полем.
- **Перф**: `acrylic-perf.spec.ts` (полный набор): медианный кадр acrylic ≤
  glass × 1.5 + 4ms; замер 16.70/16.70/16.70 ms (BASELINE.md).

## Чего этот ADR НЕ делает

- Не трогает контракт и движок Liquid Glass (ADR-0003): гейт переиспользован,
  лензинг/кэш/деградации LG как были. Follow-up (вне ADR): LG-инлайн
  переживает forced-colors — закрыть тем же media-паттерном, что acrylic.
- Не вводит пресеты acrylic-in-app / acrylic-background / mica (ADR-0004
  Решение 1) — один acrylic; пресеты = отдельное решение при нужде.
- Не переименовывает `glass` (вердикт владельца) и не меняет публичный
  экспорт `material.css`.
- Не заводит magic-величин: Λ=0.7 DECLARED (демо-калибровка, замок);
  48px/180% — существующие ступени; регион фильтра −25%/150% — DECLARED
  (ядро гаусса, хвост >1.5σ перцептивно пуст); зерно — ассет одной генерации.

## Последствия

- Acrylic перестал быть «стеклом с зерном»: у него своя физика (зажим яркости)
  и измеримо СИЛЬНЕЕ гарантия текста, чем у glass (8/10 против 6/10).
- Долг «множитель C» закрыт выводом; коридорная математика ADR-0004 получила
  первый нетривиальный коридор.
- Материалы находимы по файлам; ось осталась одноуровневой:
  `data-material="solid | glass | acrylic"` рядом с `data-theme`.
- Перф-класс закреплён числом и гейтом: рецепт живёт целиком в композиторе.
