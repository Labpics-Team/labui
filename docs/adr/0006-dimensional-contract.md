# ADR-0006. Dimensional contract: шкала как закон и статусная дисциплина размеров

Статус: принято (владелец, задача #121, 2026-07-09). §7 «Открытые вопросы» — гейт
владельца: каждое решение оттуда — отдельная волна нормализации со своим
blast-radius. Исполняемая форма закона — `docs/dimension-contract.md` (§1–§7)
и гард `packages/colors-stub/test/no-magic-dimension.ts`; реализация этого ADR —
байт-идентичная токенизация (задача #121, PR 2).

Фактическая база — read-only аудит размерной системы 2026-07-09 (задача #121):
1 611 деклараций spacing/size/radius/border/type в react+core (926 + 685),
198 «магических» употреблений из 33 уникальных значений (~99 решений, ×2 из-за
твинов react/core), 618 фолбэк-кешей `var(--lab-X, <литерал>)` с ровно одним
дрейфом. Ключевые числа воспроизведены ниже — документ самодостаточен.

## Контекст

`docs/dimension-contract.md` уже декларирует закон (rem-модель, ось контролов,
концентричность, хэйрлайны, фолбэк-кеши, z-шкалу), но кодовая поверхность ему
соответствует неравномерно:

- Доля на токенах по категориям: type **96.4%**, border/focus **95.7%**,
  radius **90.2%**, spacing **63.8%**, size **21.3%** — размеры-габариты
  остались грязной зоной.
- Ось высот контролов `--lab-size-control-h-{s,m,l}` (32/40/48) объявлена в
  `tokens.css` и имеет **0 потребителей** — button/pin-input держат те же
  значения приватными литералами: два источника правды на одно значение.
- Закон концентричности (§3 контракта) **нигде не исполняется**: 0 вызовов
  `concentricRadius()`; вложенные радиусы — константа 4px независимо от inset.
- Семейств высот контролов фактически четыре: {32,40,48} declared,
  {30,36,44} (menu/select), {28,36,44} (pagination) и natural {30,42,≈63}
  у button/полей — `min-height` не ограничивает natural-перелив.
- Цветовая система (lab-colors) уже живёт статусной дисциплиной
  DERIVED/DESIGN-CHOICE; размерная — нет: «почти-одинаковые» боксы
  14/16/18/20/22/24 сосуществуют без статуса и связи.

Этот ADR фиксирует шкалы как закон потребления, вводит статусную дисциплину и
называет целевые законы нормализации, честно разделяя: что кодифицируется
байт-идентично СЕЙЧАС, а что — видимое изменение и ждёт гейта владельца.

## Решение

### §1. Шкала как закон — закрытые наборы потребления

Размерное значение в компоненте обязано быть ступенью одной из пяти шкал ниже
(потребляется `--lab-*` токеном), деривацией §2 или хэйрлайном (контракт §4).
Наборы закрыты: новая ступень = новый ADR, не новый литерал.

| Шкала | Ступени (px @100%) | Токены |
|---|---|---|
| spacing (pad/margin/gap/inset) | {0, 1, 2, 4, 8, 16, 24, 32} | `--lab-space-{0,xs,sm,md,lg,xl}`; 1/2px — хэйрлайны §4 |
| высоты контролов | {32, 40, 48} | `--lab-size-control-h-{s,m,l}` |
| глиф-боксы | {12, 16, 20, 24} | `--lab-size-control-{s,m,l}` + ступень 24 |
| radius | {0, 2, 4, 6, 8, 16, full} | семантика `--lab-radius-{control,card,pill,circle,concentric-min}` поверх лестницы примитивов |
| ширины оверлеев | {11, 12, 14, 16, 18, 20, 22, 24, 28, 32, 40} rem | `--lab-size-overlay-*`, лестница as-is |

Обоснования по шкалам:

- **spacing** покрывает ~99% живого потребления (`xs`×76, `sm`×75, `md`×52,
  `lg`×21, `xl`×2 + хэйрлайны) — **НЕ расширять**. Ступени `space-3` (12px),
  `2xl`, `3xl` и все числовые сегодня мертвы (0 потребителей); их оживление —
  запрос через ADR, не тихое употребление.
- **высоты {32,40,48}** — доминирующее семейство (button, pin-input,
  tags-input), целиком на 4px-сетке; канонические токены уже существуют,
  миграция лишь подключает их (байт-идентично).
- **глиф-боксы {12,16,20,24}**: 12/16/20 заземлены живым Figma
  (Size S/M/L ↔ Unit px/6/7/8, контракт §2); 24 — фактическая ступень
  checkbox l / kbd m / loader md.
- **radius**: фактическое потребление {0,2,4,6,8,16,full} целиком внутри
  существующей лестницы — работа не в шкале, а в исполнении концентричности
  (§4) и замене прямых примитивов `sm`/`md` (×24/×12 употреблений) семантикой.
  Реалайнмент лестницы примитивов с Figma-лестницей — отдельная волна
  (контракт §3, открытый пункт там же).
- **оверлеи**: лестница из 11 значений токенизируется as-is байт-идентично;
  нормализация её состава — отдельная волна.

### §2. Статусная дисциплина: DERIVED | DESIGN-CHOICE

Как в lab-colors, каждое размерное значение обязано иметь статус:

- **DERIVED** — выводится формулой из другого значения; в коде живёт
  calc()-выражением над токенами/ручками, а не копией числа.
- **DESIGN-CHOICE** — свободный выбор владельца, задокументированный у ступени
  шкалы (комментарий в конфиге токенов / этом контракте).

Легализованные деривации:

- **`thumb = track-h − 6`** — switch и slider уже байт-идентично консистентны
  (thumb 14/18/22 при track-h 20/24/28);
- **`dot = ring/2`** — точка radio (контракт §2, заземлено Figma small/medium).

Микрошкала толщин индикаторов — DESIGN-CHOICE as-is: loader stroke {2,3,4},
slider track {4,6,8}, progress {4,8,12}; 3px не снапается на сетку без
видимого сдвига. Вместе деривации и микрошкала легализуют **22 из 30**
вне-сеточных употреблений (аудит §8); остаток — §7.

### §3. Целевой закон паддингов контролов — ЦЕЛЬ, не статус-кво

```text
pad-y = (h − line-height)/2 − border
pad-x = k · h,  k фиксирован на класс компонента
```

Честный разрыв: сегодня pad-y взят соседними ступенями spacing-лестницы
(xs/sm | sm/md | md/lg), высота из них не выводится; совпадение на m —
случайность. Natural-рендер button/полей = 30–32 / **42** / **≈63** при
заявленных 32/40/48 (`min-height` не ловит перелив; на l перелив +15px:
pad-y 16 + font lg×1.5). Фактический pad-x/h = 0.25 / 0.40 / 0.50 —
монотонный произвол без константы.

Применение закона = видимое изменение геометрии каждого контрола = отдельная
волна с гейтом владельца. **НЕ в PR задачи #121.**

### §4. Закон концентричности — ЦЕЛЬ

`r_outer = r_inner + gap`; исполняемая форма — контракт §3:
`r_inner = max(r_outer − inset, --lab-radius-concentric-min)` через
`concentricRadius()` / `litConcentricRadius()` (`packages/core/src/css.ts`).

Статус-кво: **0 вызовов** в компонентах; все вложенные радиусы захардкожены
константой 4px (`--lab-radius-sm`) независимо от inset. Из 9 живых пар
outer→inner закон осмысленно не исполняет ни одна: 6 расходятся на ±2…+6px
(menu/select/combobox/dialog +2, tags-input −2, card +6), popover совпадает
арифметической случайностью, switch/avatar — pill/full по построению.

Нормализация (6 пар, видимые ±2…+6px) — гейт владельца, отдельная волна.

### §5. Фолбэк-кеши и гейты

- Фолбэк = кеш канона (контракт §5) — правило глобальное; модель уже работает:
  618 фолбэков, 617 честных, единственный дрейф —
  `packages/materials/src/material.css:107` `var(--lab-radius-card, 12px)` при
  каноне 16px, в слепой зоне гарда (гард не сканировал `packages/materials`).
  Слепая зона закрывается, дрейф чинится (PR 2, отдельным коммитом).
- Волна миграции (контракт §6): компонент попадает в `MIGRATED` только
  полностью переведённым (magic-length/magic-radius = 0) тем же PR.

### §6. Байт-идентичность кодификации

Токенизация статус-кво меняет НОЛЬ пикселей: `<литерал>` →
`var(--lab-X, <тот же литерал>)` по модели фолбэк-кешей; деривации §2
записываются выражением с текущим численным значением. Доказательство —
снапшот computed styles всех компонентов до/после (diff = ∅) в PR миграции.
Все видимые нормализации (§3, §4, §7) — отдельные волны, каждая с гейтом
владельца.

### §7. Открытые вопросы — гейт владельца

До решения спорные значения остаются литералами, их компоненты — вне
`MIGRATED`-правил гарда (фолбэк-правило §5 действует на них как на всех).

- **(а) menu/select {30,36,44} и pagination {28,36,44} → ось {32,40,48}?**
  +2…4px видимых, ~10 употреблений; 30px — вне собственной 4px-сетки.
- **(б) avatar status-dot s = 10px** (вне сетки): ступени {8,12,16}
  (s: −2px видимых) или деривация от диаметра?
- **(в) popover arrow 10px** (0.625rem): tooltip несёт 8px (на сетке) —
  унифицировать на 8 (−2px) или узаконить 10 ступенью?
- **(г) checkbox `tiny` = 14px** — оси tiny в контракте НЕТ (в Figma
  `Size=tiny` ≡ побайтная копия M — недоделка макета, контракт §2): снести
  вариант или дождаться значения владельца в Figma?
- **(д) checkbox vs radio — одна Figma-ось, два маппинга**: radio m=16
  (Size/M) при checkbox md=20 (Size/L), плюс checkbox l=24. Какой маппинг
  канонический для квадратных контролов?

## Следствия

- PR 2 задачи #121 — байт-идентичная токенизация: 56 файлов (26 css + 30 lit),
  паттерн `<литерал>` → `var(--lab-X, <тот же литерал>)`; подключение
  `--lab-size-control-h-*`; деривации thumb/dot выражениями; расширение гарда
  (glob на `packages/materials` + пополнение `MIGRATED`); фикс дрейфа
  materials отдельным коммитом; доказательство байт-идентичности — снапшот
  computed styles до/после.
- Открытые вопросы §7 не блокируют миграцию значений на шкалах: спорное
  остаётся литералом вне `MIGRATED` до решения владельца.
- Расширение любой шкалы §1 — только новым ADR.
