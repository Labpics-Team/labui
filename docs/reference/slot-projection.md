# Проекция именованных слотов

Vue slots, Svelte snippets и строковые SSR bindings сохраняют созданные
потребителем узлы внутри внутреннего `lab-slot`. Его native shadow slot передаёт
контент принимающему компоненту. Framework продолжает управлять своими детьми:
адаптер не переносит их, не клонирует DOM и не разбирает результат snippet.
Публичные slot/snippet API не меняются. Solid передаёт непосредственных детей
с их `slot` атрибутами; React использует свой обычный node API.

Обычный `display:contents` wrapper устраняет свою коробку, но сохраняет границу
для CSS: `::slotted` принимающего компонента выбирает wrapper, а не вложенный
SVG. Поэтому управление размерами выделено в общий `slotSizeCss` из
`packages/core/src/slot-projection.ts`. Компонент передаёт нужные ему inline/block
size через `--lab-slot-inline-size` и `--lab-slot-block-size`. Тот же helper
задаёт размеры непосредственного элемента в Lit/React. Внутри `lab-slot` только
эти два свойства применяются к непосредственным корням переданного содержимого.

Без заданной геометрии сохраняются естественные размеры и пользовательский CSS.
Вложенный независимый `lab-slot` сбрасывает контракт в своей shadow cascade:
геометрия внешнего слота не переходит на его содержимое. Принимающий компонент
может задать новый размер через внешнее `::slotted`; стандартный порядок shadow
cascade даёт ему приоритет над внутренним значением по умолчанию. Другие свойства,
внутренности пользовательских custom elements и тексты адаптер не переписывает.

SSR выводит декларативный shadow root проекции. Поэтому размеры действуют до
запуска JavaScript. При регистрации общий `LabElement` один раз определяет
проекцию; существующий shadow root сохраняется. У проекции нет observers,
обработчиков событий, измерений и фонового цикла.

Проверка `node apps/docs/tests/slots-packed.mjs` устанавливает готовые пакеты в
отдельный проект и использует настоящие Vue/Svelte compilations. Она проверяет
SVG, вложенный custom element, SSR без JavaScript, отложенную hydration,
изменение и повторное создание содержимого, текстовые fragments, несколько
корней, escaping динамического имени слота и сохранение пользовательского узла.

Основания: [Svelte snippets](https://svelte.dev/docs/svelte/snippet),
[Bits UI child snippet](https://bits-ui.com/docs/child-snippet),
[CSS Cascade — encapsulation contexts](https://www.w3.org/TR/css-cascade-6/#cascade-sort).
Передача props в snippet остаётся подходящим способом делегировать произвольные
свойства у другой API-модели; текущим slots/snippets LabUI она не требуется.
