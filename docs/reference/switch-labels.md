# Подписи Switch

Switch располагает подписи в порядке **левая подпись → дорожка → правая подпись**.
У каждой стороны своя видимость. Текст правой стороны передаётся через прежний
default slot или React `children`.

| Свойство | Атрибут Web Component | По умолчанию | Поведение |
| --- | --- | --- | --- |
| `labelStart` | `label-start` | `''` | Текст перед дорожкой. |
| `hideLabelStart` | `hide-label-start` | `false` | Исключает левую подпись из геометрии и доступного имени. |
| `hideLabelEnd` | `hide-label-end` | `false` | Исключает правую подпись из геометрии и доступного имени. |

```html
<lab-switch label-start="Сеть">Wi-Fi</lab-switch>
```

```tsx
<Switch labelStart="Сеть" hideLabelEnd>Wi-Fi</Switch>
```

Пустая строка, пробельный текст и React `false` не создают подпись или промежуток.
Пустые React fragments и массивы также пропускаются; число `0` остаётся текстом.
Обычные текстовые обёртки (`span`, `em`, `strong` и подобные) без содержимого
пропускаются рекурсивно. Богатый текст, именованные элементы и неизвестные custom
components сохраняются. React оставляет `children` смонтированным и после mount
наблюдает фактический DOM: самостоятельное обновление дочернего компонента меняет
видимость подписи и имя input без render родителя.
Именованные `icon-on` и `icon-off` находятся внутри дорожки и не считаются подписью.
Изменения текста, в том числе внутри обёртки, и slot assignment обновляют имя
Web Component, включая текст, назначенный через внешний слот, и открытый ShadowRoot.

CSS-класс или обычный inline style сохраняет известный текст подписи в SSR.
`hidden`, `aria-hidden="true"`, `display:none`, `visibility:hidden/collapse`
и `content-visibility:hidden` исключают caption из имени. После mount Switch
проверяет computed style при изменении содержимого и атрибутов подписи;
`opacity:0` не исключает имя.
Неразрешимое inline-выражение видимости или значение `display` с зависимой от движка
поддержкой использует fallback до проверки DOM.

Показанные подписи с известным непустым текстом или именем именуют checkbox input через уникальные
`aria-labelledby` в порядке слева направо. Когда таких подписей нет, имя input
берётся из `aria-label`. Задайте его для переключателя без показанного текста и
для непрозрачного содержимого. В SSR React-компонент с неизвестным результатом
использует это имя до проверки DOM. Закрытый custom element без публичного имени
сохраняется; он также использует fallback и не создаёт пустую ссылку `aria-labelledby`.

Native `<title>` непосредственно внутри SVG именует правую сторону, включая
скрытый title и прозрачный React Fragment вокруг него.
Имя вычисляется для цепочки input → собственная обёртка подписи. Произвольный
`aria-labelledby` у её потомка не создаёт новую цепочку ссылок: внешний,
циклический или пустой IDREF без другого известного имени сохраняет fallback.

SSR-функции четырёх адаптеров принимают существующее свойство ядра `ariaLabel`
и передают его как `aria-label`. Например:

```ts
import { renderSwitch } from '@labpics/ui-vue/ssr';

const markup = renderSwitch(
  { hideLabelEnd: true, ariaLabel: 'Wi-Fi' },
  { default: 'Скрытая подпись' },
);
```

Включите результат в серверный HTML по [процедуре SSR](../ssr.md). Подписи,
их видимость и имя input присутствуют до hydration. Astro-обёртка также
принимает обычный атрибут `aria-label`.
