# Каталог компонентов

[Семантический реестр](../../catalog/registry.json) определяет границы семейств,
категории и соответствие Lab UI v2.1. Набор Figma может означать семейство,
представление, часть или материал. Части показаны внутри семейства; они не
становятся самостоятельными пунктами каталога. Самостоятельные компоненты
Figma без набора вариантов входят в тот же реестр.

## Источники и проекции

| Данные | Источник |
| --- | --- |
| Семейства, категории, роли источника и сопоставления | `catalog/registry.json` |
| Web props, события, слоты и имя элемента | [AST-анализатор](../../packages/adapter-codegen/src/analyze.ts) |
| Экспорты React | [Публичный модуль React](../../packages/react/src/index.ts) |
| Публичные Compose функции и объекты | исходники `native/compose`, наблюдение в `catalog/native-api.generated.json` |
| Текст, анатомия, состояния и живые примеры | [Модули документации](../../apps/docs/src/components/) |
| Каталог для документации | `catalog/catalog.generated.json`, результат соединения источников |

Генератор проверяет ссылки на семейства, уникальность источников и doc slugs,
существование Web API, React exports, Compose symbols, профилей и руководств.
Ключи `web.props` сверяются с существующим анализатором; второй список props
не ведётся. Модули документации сохраняют собственные примеры и текст.

Профили `components.json` ссылаются на источник через `sourceRef.key` в формате
`type/page/name`, например `component-set/Switch/Switch`. URL, страница, имя
и роль определяются реестром и не копируются в профиль. Генератор проверяет
существование ссылки и принадлежность тому семейству, которое использует
профиль. Для измерения вложенного слоя `variant` задаёт точные свойства
варианта Figma, а `path` — последовательность имён дочерних слоёв. При сверке
REST cache такой selector должен однозначно выбрать реальный вариант.

## Что означает доступность

«Есть API» означает обнаруженную публичную реализацию. Это не обещание
полного соответствия авторским темам, размерам и состояниям.
`sources[].uses[].web` и `native` задают сопоставление только в пределах
указанного `scope`. Отсутствующая привязка означает «не сопоставлено», даже
если семейство уже имеет код и живую документацию.

Например, у Progress есть Web API и линейное представление, но нет привязки
Circular progress. Calendar имеет запись каталога без Web/Compose API.
Combobox и другие расширения не получают выдуманный одноимённый источник.
Ни существование файла, ни `stable` в прежнем doc-модуле не доказывает
визуальную готовность всего семейства; каталог не выводит её автоматически.

Без параметра `component` открывается обзор. Известное семейство без
реализации имеет собственную страницу с составом. Неизвестный адрес
показывает сообщение и ссылку на каталог, сохраняя запрошенное имя.

## Обновление

Запустите `pnpm catalog:generate`, затем `pnpm catalog:check`.
Сборка документации проверяет, что сохранённая проекция соответствует
исходникам. Авторские ссылки используют публичный Community URL,
страницу, имя и роль; приватные ключи файла, node IDs и подписанные
изображения в реестр и профили не переносятся.

Для повторной проверки локального REST cache передайте генератору
`--source-sets <json>` и `--source-components <json>`. Все наборы из cache
должны быть представлены ровно один раз. Компоненты без
`containingComponentSet` проверяются в обе стороны: каждый источник имеет
классификацию, каждая ссылка реестра существует в cache. Самостоятельные
составы, части и материалы сохраняют свои роли даже при совпадении имени
с набором вариантов. Исключения `sourceExclusions` перечисляют точные
страницы библиотек Icons и Flags с причиной: их графические ресурсы не
являются семействами UI-компонентов. Неизвестная страница или удаление
самостоятельного источника из реестра завершают проверку ошибкой.
JSON cache остаётся локальным.

До сведения Web и native веток передайте `--native-root <checkout>`.
Генератор извлекает публичные символы из непосредственно прочитанных
`*.kt` в каталоге `pics/lab/ui`. Фиксируются SHA-256 имён и содержимого этих
файлов с нормализованными переводами строк. Обычная сборка и `--check`
сверяют содержимое и символы с сохранённым наблюдением без обращения к Git:
исходный snapshot без `.git` поддерживается. Сохранённый commit нужен только
для ссылки на исходник. Если содержимое изменилось, `catalog:generate`
обновляет ссылку по последнему commit тех же путей; для этого прочитанные
файлы должны быть отслеживаемыми и чистыми. Неизменённая генерация также
работает без Git. Изменение README, вложенных каталогов или самого каталога
компонентов не меняет наблюдение. Проверяются обе сохранённые проекции: API и каталог.
При наличии `native/compose` в текущем репозитории используется он.
В Web-only checkout сохранённое наблюдение подтверждает конкретные исходники,
не текущее состояние внешнего native checkout и не выполнение на пяти платформах.
