# Серверный рендеринг

`@labpics/ui-core/ssr` устанавливает минимальные DOM API синхронно, сохраняя
существующий `customElements` и зарегистрированные элементы. После завершения
импорта доступны синхронные `renderToString` и функции `renderX` веб-адаптеров.
Их результат содержит declarative shadow DOM до подключения JavaScript.

Явные свойства, которые нельзя восстановить из HTML-атрибутов, переносятся
в `data-lab-inputs`: например, `collapsible: false` при начальном `true`,
`null` и массив для свойства без атрибута. Генератор передаёт отсутствующие
свойства через `noChange`, сохраняя начальные значения компонента. Значения,
уже отражённые в атрибутах, повторно в запись не включаются.

Запись принимает JSON-совместимые данные: строки, конечные числа, булевы
значения, `null`, массивы и обычные объекты. Необязательные поля объекта
со значением `undefined` опускаются. Функции, экземпляры классов и циклические
структуры в переносимых свойствах вызывают `TypeError` на сервере; обработчики
событий подключаются клиентским адаптером и в запись не входят.

При регистрации элемента восстанавливаются только объявленные входные
свойства, без внутреннего `state`. Это происходит один раз, до
`connectedCallback`: последующее восстановление текста, введённого пользователем
до загрузки JavaScript, сохраняет приоритет. Изменение записи после запуска
не сбрасывает текущее состояние; для обновлений используются обычные свойства.

Готовая строка `renderX` и запуск Lit-элемента проверяются отдельно от
гидратации дерева конкретного фреймворка. Наличие этого SSR-helper само
по себе не означает поддержку серверного рендера обычного Vue/Solid/Svelte
компонента и последующей гидратации его слотов.

Используется `installWindowOnGlobal` из поставляемого subpath
`@lit-labs/ssr/lib/dom-shim.js` версии 4.1.0. У пакета нет ограничения `exports`,
каталог `lib` входит в опубликованные файлы. Передача существующего реестра
через штатный `props` сохраняет его и при отсутствии `window` self-reference
в минимальном DOM этой версии.

`install-global-dom-shim.js` той же версии сначала ждёт проверку CSS imports.
Его top-level await позволяет соседним статическим импортам компонентов
выполниться до установки DOM и пропустить регистрацию. LabUI использует
CSS-строки и файлы: CSS module loader остаётся настройкой приложения,
серверный bootstrap LabUI не устанавливает этот необязательный hook.

Проверка `apps/docs/tests/kbd.spec.ts` запускает собранный SSR-адаптер в новом
Node-процессе, проверяет сохранение предварительно установленного реестра,
затем гидратирует DSD и обновляет компонент в Chromium и WebKit.

Первичный источник: [DOM shim 4.1.0](https://unpkg.com/@lit-labs/ssr@4.1.0/lib/dom-shim.js),
[асинхронная установка](https://unpkg.com/@lit-labs/ssr@4.1.0/lib/install-global-dom-shim.js).
Семантика булевых атрибутов и отражения свойств:
[Reactive properties](https://lit.dev/docs/components/properties/).
