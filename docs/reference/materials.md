# Материалы

`@labpics/ui-materials` оформляет поверхности `.lab-material` в режиме
`data-material="solid"`, `"glass"` или `"acrylic"`. Классы `lab-material--base`,
`lab-material--muted`, `lab-material--soft`, `lab-material--subtle` и
`lab-material--elevated` выбирают вариант поверхности. Без них используется `base`.

Режим наследуется от ближайшей области `data-material`, в том числе через
Shadow DOM и слоты. Явный `solid`, пустое или неизвестное значение останавливает
внешний режим и даёт Solid. Без заданного режима поверхность тоже использует Solid.

## Подключить CSS

Подключите тему Lab UI и стили материалов в документе до первого paint:

```ts
import '@labui/colors/contract.css';
import '@labpics/ui-materials/material.css';
```

`contract.css` задаёт семантические токены `--lab-*` и разрешает области
`data-theme` / `data-contrast`, включая настройки ОС. Он обязателен также при
использовании `materialCss` и SSR. В серверном HTML тема должна загружаться
вместе со стилями страницы до hydration; одних скопированных значений цветов
недостаточно для работы контекста.

Для статических стилей Lit используйте строку `materialCss`; тема остаётся
подключённой в документе:

```ts
import { materialCss } from '@labpics/ui-materials/css';
import { LitElement, html, unsafeCSS } from 'lit';

const materialStyles = unsafeCSS(materialCss);

class MaterialSurface extends LitElement {
  static styles = [materialStyles];

  render() {
    return html`<div class="lab-material lab-material--elevated"><slot></slot></div>`;
  }
}

customElements.define('material-surface', MaterialSurface);
```

`materialCss` имеет тип `string` и совпадает с содержимым `material.css`.
Оба представления собираются из одного CSS. Таблица нужна в каждом документе
и ShadowRoot, где заданы области материала или оформляются поверхности:
селекторы документа не проходят внутрь Shadow DOM.

Разрешённые тема и контраст наследуются через host и слоты. Если `data-theme`
или `data-contrast` задаются внутри ShadowRoot, подключите `contract.css`
в этот ShadowRoot. Для наследования внешней темы отдельное подключение
в каждом компоненте не требуется.

Режим материала тоже передаётся через CSS-наследование. Цветовые токены
разрешаются на самой поверхности; локальные переопределения `--lab-*` сохраняются.
Свойства с префиксом `--_` служебные и не входят в публичный API.

## Подключить и отключить движки

После отрисовки подключите движки к элементу поверхности `content`:

```ts
import { mountMaterialRuntime } from '@labpics/ui-materials';

const dispose = mountMaterialRuntime(content);
```

`content` — элемент `.lab-material`, `[data-veil]` или контейнер с такими элементами.
Подключение включает его DOM-поддерево и элементы, назначенные его слотам, с их потомками.
Резервное содержимое слота входит в DOM-поддерево контейнера.
Функция принимает `Element` или `Document`; без аргумента использует документ.
Для поверхности внутри Shadow DOM передайте её элемент: подключение к документу
не обходит вложенные ShadowRoot. При отключении компонента вызовите `dispose()`;
при повторном подключении вызовите `mountMaterialRuntime` заново.

Движки читают вычисленный CSS-режим поверхности. Изменения `data-material`,
`data-theme`, классов, атрибута `style`, доступных предков и назначения слота вызывают
повторную проверку. Новые поверхности в наблюдаемых DOM-поддеревьях подключаются
автоматически. Скрытые обёртки слота внутри чужого закрытого ShadowRoot требуют
участия компонента, которому принадлежит этот ShadowRoot: внешний код
не может наблюдать их изменения.

Создание нового ShadowRoot после подключения само по себе не даёт обычного DOM-уведомления.
Компонент, который создаёт его позднее, после завершения отрисовки вызывает
`mountMaterialRuntime` для отрисованной обёртки или поверхности. Это нужно также
при отложенном определении пользовательского элемента: `whenDefined` сообщает
о завершении определения, а отрисовка может закончиться позже. Пересекающиеся
подключения разделяют один ресурс на поверхность; последний `dispose()` освобождает его.

Без JavaScript остаётся CSS-оформление. Без поддержки размытия фона, при
`prefers-reduced-transparency: reduce`, `prefers-contrast: more` или
`forced-colors: active` поверхность переходит к непрозрачному оформлению.

## Progressive blur

`data-veil="top|bottom|left|right"` задаёт край размытия. `--lab-veil-strength`
принимает CSS-длину, например `1.5rem`, `calc(1rem + .5em)` или `10cqw`;
число без единицы сохраняет прежний смысл px. Длина вычисляется на поверхности.
Отсутствующий и пустой токены дают 24 px, явный `0px` снимает эффект.
`--lab-veil-feather` принимает такую же длину или `auto`.
Явный `--lab-veil-stops` полностью задаёт профиль и перекрывает `strength`.

Относительные единицы и выражения требуют CSS Properties and Values API и
container style queries. Значения по умолчанию, числа и длины в px работают без
этих возможностей. При ошибочной активной длине или невозможности её измерить
runtime сообщает ошибку и снимает полосы. Служебные таблицы стилей используются совместно
в документе и ShadowRoot и удаляются после отключения последней поверхности.
Смена системной темы, контраста и прозрачности перечитывает настройки через
подписки runtime независимо от возможностей CSS-измерения.

## Card и серверный HTML

`lab-card` подключает стили материалов и движки самостоятельно; тему подключает
приложение. У `variant="elevated"` материал применяется к области Content;
media остаётся снаружи.
`outlined` и `filled` используют свои статические заливки.

Card задаёт радиус самой поверхности Content: внешние углы следуют рамке,
а стык с изображением или назначенным media остаётся прямым. Это сохраняет
границу backdrop-фильтра и внутри прокручиваемого контейнера. Пустой media
не создаёт стык; строка React media из одних схлопываемых HTML-пробелов
не создаёт область. Серверный HTML и последующие назначения слотов используют
то же правило. Геометрия принадлежит Card, рецепт эффекта — Materials.

`imageSrc` задаёт одно изображение для верхней области и декоративной подложки
карточки. Изображения самостоятельно заполняют свои области; текст и действия
остаются над материалом Content. Без `imageSrc` произвольный `media` не создаёт
такую подложку автоматически.

В фиксированной рамке изображение занимает остаток после Content; постоянной
высоты media нет. Без заданной высоты используется естественная пропорция
изображения. `header` заменяет стандартную текстовую группу, а `footer` содержит
обычную кнопку или ссылку действия.

Серверный HTML содержит стили в каждой декларативной Shadow DOM карточки.
На клиенте экземпляры используют общий статический `CSSResult` класса.

## Расчёт контраста

### Sheet

У Sheet есть собственный профиль Body: Elevated/01 поверх фона, тематическая
смесь Elevated/02, затем Gaussian blur. В Light используется Color Dodge,
в Dark — Overlay. Последовательность и преобразование авторского радиуса
в sigma принадлежат `materials/src/profiles/sheet.ts`; web и Windows проецируют
эти данные. Solid и повышенный контраст используют Grouped/Secondary.

Web-профиль работает через SVG backdrop в Chromium. При отсутствии этой
возможности остаётся прежний CSS blur/tint; его совпадение с авторским Sheet
не подтверждено. Glass сохраняет текущую рефракцию и принимается отдельно.
Обычные пять material tiers и Card не используют профиль Sheet.

Авторские параметры noise сохранены как исходные данные. Значение size 0.2
не имеет подтверждённой проекции в пиксели: общее зерно Acrylic не подставляется
вместо него. Точность noise и Ghost, полный Dark-эталон и native raster остаются
отдельными предметами визуальной приёмки.

`normal` сохраняет авторские краски. Например, вторичный текст тёмного Sheet
на чередующемся чёрном/белом фоне после всех слоёв даёт около 3.8:1 — обещания
4.5:1 для него нет. В `more` проверяются primary и secondary на реальном
непрозрачном Body. См. [контракт контраста](./contrast.md).

Первичные источники: [Lab UI v2.1](https://www.figma.com/community/file/1527814209910933331/lab-ui-components-icons-guides-lab-ui-v2-1),
[Figma Effect API](https://developers.figma.com/docs/plugins/api/Effect/).

### Общие material tiers

`evaluateTier` принимает необязательный `TierFill.solid` — отдельный непрозрачный
цвет для расчёта Solid. Без него используется композиция `tint` поверх `base`.
Результат относится к переданным цветам, кандидатам текста и диапазону фона;
назначение цветов текста компонентам задаётся отдельно.
