# Liquid Glass — эталоны производительности (до/после)

Горячий путь движка: `packages/materials/src/engine/liquid-glass.ts`.
База ветки — PR #88 (rim-skip `buildMap`, байт-идентичные goldens).

Регенерация чисел: `pnpm --filter @labpics/ui-materials bench`
(детерминированный node-бенч `__computeDisplacementField` — то самое
синхронное CPU-время главного потока, которое воркер уносит с потока, а
SDF-кэш срезает при смене depth). Абсолютные µs привязаны к рантайму (tsx/V8)
и НЕ гейт CI — ценность в отношении ДО/ПОСЛЕ на одной машине. Счётчиковые
метрики (полные пересчёты поля, childList-мутации, хит-рейт кэша) —
детерминированы и гейтятся в тестах.

## A. CPU одной сборки карты (µs/сборка, медиана) — синхронно на главном потоке

Замер: этот бенч, машина автора, tsx/node. Числа ДО сняты на базовой ветке
(ce6b5d5, без SDF-кэша) — это COLD-сборка (первый билд геометрии, реальный
first-paint). ⚠️ На ЭТОЙ ветке `pnpm bench` повторяет одну геометрию → SDF-кэш
греется → per-case числа отражают WARM-переиспользование (ниже COLD). COLD-цена
одной новой геометрии не изменилась; выигрыш — в переиспользовании (depth-свип,
секция B). Столбец «после (воркер)» = 0 на главном потоке (работа уходит в Web
Worker; фолбэк без воркера сохраняет COLD-цифры ДО).

| кейс                 | device px | ДО (µs) | после |
|----------------------|-----------|--------:|-------|
| small-square-dpr2    | 96×96     |    52.8 | —     |
| medium-card-dpr2     | 640×400   |   873.2 | —     |
| large-panel          | 1024×1024 |  1011.3 | —     |
| large-panel-dpr2     | 2048×1536 |  3782.8 | —     |
| large-circle         | 1024×1024 |  1477.4 | —     |
| dpr3-clamped         | 640×640   |  1059.7 | —     |

Вывод: большая панель @dpr2 = **3.78 мс** синхронного джанка на кадр сборки —
главная мишень выноса в воркер (критерий потолка **а**).

## B. Свип depth-слайдера (критерий потолка «б»)

Depth входит в ключ кэша → каждый тик = полная пересборка той же геометрии.

| метрика                                  | ДО | ПОСЛЕ (SDF-кэш) |
|------------------------------------------|----|-----------|
| 360×220 @dpr2, 21 позиция, мс/свип        | 21.7 | **10.3** (2.1×) |
| µs/тик (тёплый кэш)                        | 1031.8 | **491.9** (−52%) |
| sdRoundRect на depth-DECREASE/reuse       | полный рим | **0** ✓ счётчик |
| sdRoundRect на depth-INCREASE             | полный рим | только дельта-кольцо |

Разложение поля (360×220@dpr2): sdRoundRect(sqrt) = **42.9%** цикла поля
(894µs полный vs 510µs profile-only). SDF-поле от depth НЕ зависит → grow-only
кэш дистанций (Float64, byte-identical) закрывает «0 полных пересчётов поля».
Замок: счётчик `__fieldStats().sdfComputes` (мутация кэша/ключа роняет тест),
golden byte-identity (21 хеш), memory-cap SDF_CACHE_CAP=4 + idle-release.

## C. Смена параметров без перестройки DOM (критерий потолка «в»)

| переход                                  | ДО | цель ПОСЛЕ |
|------------------------------------------|----|-----------|
| refraction/dispersion в пределах структуры | 0 childList (только атрибут scale) | 0 (сохранить) |
| пересечение порога dispersion 0.02 туда-обратно | **1 innerHTML-ребилд/переход** (≈10 SVG-узлов) | **0 childList** (переключение url(#id)) |

## D. Память и евикшн (критерии потолка «г», «д») — уже в базе #88, счётчики

| инвариант                                 | ДО (база) | статус |
|-------------------------------------------|-----------|--------|
| атомарный свап карты (decode → потом stamp) | есть (armStamp) | сохранить + счётчик |
| zombie-кэш ограничен ZOMBIE_CAP=12         | есть (evictZombies) | сохранить + мутационный тест на кап |
| scratch освобождается после idle 2с        | есть | решить по данным (keep-vs-release) |

## Легенда статуса потолка

- **а** сборка карты полностью вне главного потока — ДО: нет (поле синхронно).
- **б** depth = O(encode), 0 пересчётов поля — ✅ ЗАКРЫТО (SDF-кэш, 0 sdRoundRect на reuse, 2.1× свип).
- **в** смена параметров = 0 перестроений DOM — ДО: частично (порог dispersion ребилдит).
- **г** атомарный свап после decode — ДО: да (armStamp), нужен счётчик-замок.
- **д** память ограничена капами с тестируемым евикшном — ДО: да (ZOMBIE_CAP).
