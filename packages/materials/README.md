# Материалы LabUI

`src/profile.json` — общий сериализуемый авторский профиль для web и native.
Он хранит параметры эффектов и ссылки на роли Colors. RGB и opacity цветовых
ролей поступают из Colors; геометрию поверхности задаёт компонент.
Пакет экспортирует тот же файл как `@labpics/ui-materials/profile.json`.

В профиле пять исходных уровней: Subtle, Soft, Muted, Base, Elevated.
`normalRole` применяется первым, затем `blendRole`: color-dodge в светлой теме
и overlay в тёмной. `Material/02` не является непрозрачной подложкой.
`solidRole` у каждого уровня указывает на отдельный слой Solid из Figma.

Для CSS подключаются Colors и `@labpics/ui-materials/material.css`.
Один `mountMaterialRuntime(root)` обслуживает область и возвращает disposer.
Атрибут `data-material="solid|acrylic|glass"` выбирает режим; классы
`lab-material lab-material--soft` выбирают поверхность и уровень.
Для ShadowRoot, включая закрытый, вызывается тот же mount при подключении
компонента и disposer при завершении его жизненного цикла.

Web сначала размывает настоящий backdrop, затем применяет необязательную
линзу и авторский paint-тон. Chromium выполняет SVG transfer внутри
`backdrop-filter`; Firefox — обычным SVG-фильтром на отдельном захваченном слое.
Оба используют один compiler и независимые таблицы RGB на 256 значений в sRGB.
Safari смешивает Normal/Color Dodge/Overlay нативно поверх своего capture.
Текст, внешняя тень, блик и progressive veil находятся вне этих слоёв.
Одинаковые рецепты делят неизменяемый фильтр; transform и scale не создают
текстуры, DOM или новые таблицы. Локальные уровни −2/−1 размещают paints под бликом.

Компоненты размещают scrollport внутри поверхности. Для существующей поверхности
с `overflow:auto|scroll|hidden` Firefox/Safari используют absolute-контейнер размером
со scroll extent и sticky capture. Он не становится flex/grid item, не меняет gap
и следует обеим осям без scroll listeners. Только такой host наблюдает свой размер,
размеры непосредственных детей и изменения содержимого; рост и уменьшение extent
обновляют контейнер. Отключение runtime снимает все наблюдения.

Авторский `cornerSmoothing` задаётся на материале как `--lab-corner-smoothing:.6`;
обычный CSS `border-radius` сохраняет четыре исходных радиуса. Общий числовой
контур строится из дуг и кубических переходов Figma. Клип заливки/capture, блик,
тень и нормаль линзы используют его. Host не получает mask, clip-path или filter.
Расстояние до кривой вычисляется по аппроксимации с отклонением ≤1/4096 px;
контуры и участки углов кешируются, оптическое поле сохраняет симметрию и atlas.

Для изображения и обводки обычного компонента есть отдельный явный порт:

```ts
const shape = mountSurfaceShape(card, { smoothing: .6 });
// После изменения авторских стилей или темы:
shape.refresh();
// При отключении компонента:
shape.destroy();
```

Он использует размер и радиусы элемента, наблюдает resize и не включает режим
материала. Декоративные изображения получают `clip-path:var(--lab-contour-clip)`
и `inset:var(--lab-contour-inset)`, чтобы совпасть с внешней коробкой при CSS border;
`--lab-material-shadow` содержит полный CSS-стек теней. Shadow остаётся позади
содержимого. Пара `--lab-surface-stroke-width` / `--lab-surface-stroke-color`
рисует обводку внутри того же контура отдельным слоем над Content, включая его
непрозрачный Solid. Компонент размещает изображения на −2, Content — на 0/1;
обводка занимает 2 и не перехватывает события. Оба вида подключения делят кеш
геометрии. При прокрутке задние и передние декоративные слои обслуживает одно
измерение viewport/extent и один комплект наблюдений; JS на scroll отсутствует.
Эти custom properties — локальный контракт Materials. Цвет обводки
компонент связывает с семантической ролью Colors; без ширины обводки нет.
Внутри декоративного стека внешняя тень занимает −3, paint — −2, rim и внутренняя
тень — −1. Эти значения действуют только в изолированной поверхности.
Дробные CSS размеры сохраняются до растеризации линзы; transform не входит
в её локальную геометрию. Указанный автором `overflow:hidden/auto` продолжает
обрезать дочернюю декорацию. Если нужна внешняя тень, поверхность остаётся
неклипованной, а scrollport или clip изображения располагается внутри неё.

Screen-зерно под paints подтверждено REST-выгрузкой: Plugin API не возвращает
режим смешивания NOISE. Chromium и Safari используют один запечённый PNG.
Firefox получает равномерную середину диапазона штатного зерна: это приближение,
не пространственная текстура. По всем десяти авторским сочетаниям темы/уровня
его максимальная ошибка после paints не превышает **0.057852 единицы RGB**
для любого фона и значения зерна; округление compositor учитывается отдельно.
Усиленные или иные текстуры не усредняются этим адаптером.

Диагностический `data-lab-material-grain` на поверхности показывает `spatial`,
`uniform-bounded`, `unsupported` или `none`; при `uniform-bounded` атрибут
`data-lab-material-grain-error` содержит верхнюю ошибку в 8-битных единицах sRGB.
Приватная замена `--_acrylic-noise` другим URL в Firefox даёт `unsupported`:
paints и blur сохраняются, зерно не рисуется. Штатный PNG определяется по
сгенерированному источнику `--_acrylic-noise-source`, а не по предположению о URL.
CSS до подключения runtime опускает зерно.

Backdrop radius переводится в CSS blur делением на два, как в Figma
`getCSSAsync`. Glass frost — отдельный параметр; web sigma = frost / 2 выбран
по прямому сравнению с Figma Effects/Glass. Линза и направленный внутренний
блик ещё не воспроизводят весь исходный световой рисунок. Размер noise-текстуры
также задаётся web-переводом. До mount и в неизвестном браузере остаются frost
и normal-композиция между концами авторской функции. Она точна для семи
из десяти сочетаний темы/уровня; Light/Elevated и Dark/Subtle/Elevated нелинейны,
их ошибка без SVG остаётся менее 20 единиц канала sRGB. Это ограничение renderer,
а не полное совпадение с Figma. После mount Firefox и Safari используют полную
функцию paints; рефракция остаётся доступна только Chromium.

Первый кадр стандартных Colors готов в CSS: normal-композиция и остаточный
SVG data-URL сгенерированы из `@labui/colors/contract.css`. Runtime обновляет
результат по живым scoped-ролям и делит один неизменяемый фильтр между одинаковыми
рецептами в Document/ShadowRoot. Для собственной темы `compileMaterialTheme(theme,
roles)` возвращает неизменяемый набор CSS properties для первого SSR-кадра.
Передайте числовые роли без префикса `--lab-`: encoded sRGB 0..255, alpha 0..1;
примените результат в той же области, что исходные роли Colors. Compiler чистый,
не требует DOM или solver и используется также при сборке стандартного CSS.
RGB-таблицы runtime и SSR интерполируют 256 отсчётов. Ошибка менее 0.15 RGB
между отсчётами проверена для десяти авторских recipes; произвольный рецепт
может иметь большой наклон или разрыв. Например, непрозрачный белый Color Dodge
после прозрачного Normal при фоне 0.5 RGB даёт точно 255, а интерполяция таблицы —
127.5. `materialPaintOver` сохраняет точную скалярную формулу. `fallbackError`
описывает отсутствие transfer, а не ошибку его интерполяции.
Одно только переопределение CSS-ролей без compiler сохраняет стандартный начальный
paint до mount. Native получает
тот же deterministic grain из `@labpics/ui-materials/noise.png` (48×48,
масштаб 9.6 logical px) и параметры noise из профиля.

`progressive` в том же профиле хранит исходные стили Ghost/Soft/Strong
(radius 4/12/24), ось и состав сцен. Strong в Effects — два вложенных прохода
Strong; компонент Layers/Overlay/Ghost — один Strong, несмотря на его имя.
Это разные композиции: `strong` и `overlay-ghost`. Радиусы остаются Figma
logical px; web переводит их в sigma делением на два. Noise opacity у Ghost
.04, у Soft/Strong .06; цвет и размер зерна берутся из общего `noise`.
`data-veil="top" data-veil-profile="strong"` строит оба прохода;
`overlay-ghost` оставляет один. Каждый проход содержит до шести накопительных
полос и отдельное зерно из `veil-noise.png`. Геометрия пересчитывается при
изменении размера или профиля; движение не выполняет JS. Без имени профиля
сохраняется произвольная конфигурация `--lab-veil-*`. Если у исходного frame
есть собственный paint между его эффектом и вложенным эффектом, он задаётся
дочерним `[data-veil-paint]`. Runtime размещает первый blur/noise перед ним,
вложенные проходы — после, и сохраняет порядок при resize/замене paint.

Для движущегося края `--lab-veil-axis-length` задаёт ту же CSS-длину, что высота
вертикального или ширина горизонтального veil. Полосы edge preset используют
эту длину в CSS calc; при её изменении сохраняются DOM, профиль, физические
радиусы blur и узкие области захвата. Пример: `height:var(--lab-veil-axis-length)`.
Диагональная ось продолжает пересчитываться по ResizeObserver.
Компонент передаёт свои переменные движения как
`mountMaterialRuntime(root, { motionProperties })`, чтобы изменения только этих
переменных не перечитывали paints. Они могут управлять translation и длиной
такого veil; роли, радиусы углов и рецепт материала от них зависеть не должны.
Обычные изменения стилей, темы и физического размера поверхности наблюдаются
как прежде. Список переменных берётся из той же декларации, что движение.

`compositions.sheet` связывает Body с `elevated`, тенью Shadow `modal` и внешней
обводкой `border-base`. Ghost ссылается на один `overlay-ghost`, усиливается вниз
и перекрывает Body на 32 logical px. Web использует `lab-material--sheet` для Body
и `<div data-veil class="lab-material-ghost--sheet"><i data-veil-paint></i></div>`
для Ghost. Направление и профиль поступают из общего рецепта; явные `data-veil`
и `data-veil-profile` могут их переопределить. CSS отдаёт
`--lab-sheet-ghost-overlap` для размещения Ghost компонентом. Ghost начинается
у верхней границы viewport; его высота — Body.top относительно viewport + overlap.
Равные высоты Ghost и Body в Half — частный случай, остальные четыре состояния
имеют разные высоты. Радиусы Body
32/32/0/0, размеры и положение принадлежат Sheet. Тени требуют подключённого
Shadow CSS. [Исходные узлы](../../docs/evidence/materials-20261117/figma-sheet-source.json)
содержат только прочитанные значения; скрытые Dark paints в REST разрешены
в текущем Light mode, поэтому их RGB не используются как тёмная палитра.

Runtime перечитывает роли при изменении области или темы. Линза кешируется
по локальной геометрии и DPR; учитывает все четыре пары радиусов, проценты
`calc/min/max/clamp` и общее уменьшение перекрывающихся углов CSS. Лучи идут
по нормали края через выпуклое сечение, по закону Снеллиуса; прямой край длинной
панели не тянет фон к её центру. Одна небольшая таблица оптики обслуживает
все глубины. Для круглых симметричных углов
сохраняется расчёт четверти карты. Transform меняет координаты захвата без сборки
карты, чтения профиля и изменения SVG. ResizeObserver обновляет размер.
Для достаточно больших поверхностей восемь сохранённых PNG описывают углы и
края: resize изменяет только координаты SVG, сохраняя нижнюю линзу. Применимость
вычисляется из профиля лучей; короткие поверхности, пересекающиеся углы и дробный
DPR используют полный расчёт. [Пиксельная проверка](../../docs/evidence/materials-20261117/glass-resize.md).
Перенос между деревьями пересоздаёт ссылки на локальные SVG defs. Пока область
отсоединена, временный observer ждёт её подключения без сканирования документа.
Последний disposer освобождает фильтры, наблюдателей и подписки.

Для ShadowRoot доступен `import { materialCss } from '@labpics/ui-materials/css'`.
ESM/CJS строка и типы генерируются вместе с `material.css` из одной функции;
адаптеры могут подключать ровно ту же систему внутри своего дерева.

`evaluateTier` использует независимый Solid для выбора полярности надписи
и оба paints для расчёта контраста. `resolveOnMaterial(label, paints)` также
принимает полный `MaterialPaints`; вариант с `Rgba` описывает только одну
normal-заливку. Коридор — вход о доступных пикселях, а не утверждение, что
живое видео или область Gaussian blur были измерены. Increased contrast,
reduced transparency и forced colors снимают эффекты и возвращают Solid.

Проверки: `pnpm --filter @labpics/ui-materials test`, `typecheck`, `build`,
`check-generated`; браузерные `acrylic-live.spec.ts` и
`material-lifecycle.spec.ts` проверяют реальные пиксели, темы, области,
переносы, движение и освобождение ресурсов.
