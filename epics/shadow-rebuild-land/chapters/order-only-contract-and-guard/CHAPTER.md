# Land the coherent branch as working tree; lock order-only contract + consumed-not-reinvented guard

## User Story
As a labui consumer styling elevated surfaces, I want elevation to always come from the `@labpics/ui-shadow` contract (never re-invented as ad-hoc `box-shadow` literals) and the decorative ramp to keep its RELATIVE ORDER while the external engine's absolute magnitudes remain provisional, so my surfaces stay consistent and never silently fork off the design system.

## Purpose
Two of the scope's exit-criteria are NEW invariants the existing tree does not yet lock:
1. **Order-only contract** — the shadow ramp magnitudes (alphas s1>s2>s3>s4; sizes xs<s<m<l<xl) are PROVISIONAL (Figma stub; lab-colors JND calibration pending). A test must assert ONLY the relative order labui depends on, and record the absolute-base dependency as an EXTERNAL blocker — never fabricate absolute magnitudes.
2. **Consumed-not-reinvented guard** — a component using elevation must prove its shadow comes from the `@labpics/ui-shadow` surface (`--lab-elevation-*` / `.lab-shadow-*` / the generated `shadow.css`), not an ad-hoc `box-shadow:` literal authored in component CSS.

This chapter FIRST discards the broken half-applied staged edit on main and lands the coherent `land/shadow-rebuild` tree (so the baseline typechecks), THEN adds the two locks. Both new tests must be RED-proved (fail before the invariant holds / when a violation is injected, pass after) per TDD.

## Exit Criteria
These ARE the user story's acceptance criteria — phrased Given/When/Then.
- [ ] Given the broken half-applied staged `layer.ts` edit on main, When the coherent `land/shadow-rebuild` tree is landed over it, Then `pnpm --filter @labpics/ui-shadow typecheck` exits 0 (the 14 SHADOW_LAYERS/LAYER_SHAPES errors are gone) and the working tree is internally consistent (no dangling `SHADOW_LAYERS` import anywhere).
- [ ] Given the layered shadow stack, When the build runs, Then it is generated by `@labpics/ui-shadow` consuming `--lab-shadow-alpha-*` / `--lab-surface-shadow-tint` roles via `color-mix` — there is NO hardcoded shadow colour literal in any component CSS (no-hardcoded-colour guard PASS).
- [ ] Given the decorative shadow ramp, When the order-only contract test runs, Then it asserts ONLY relative order — `SLOT_ALPHA.s1 > s2 > s3 > s4` and the five-size geometric ladder strictly increases xs<s<m<l<xl — and asserts NO absolute magnitude; the test is RED-proved (reordering any pair fails it).
- [ ] Given a component using elevation, When the consumed-not-reinvented guard runs, Then it PASSES proving every elevation shadow resolves to a `--lab-elevation-*` role / `.lab-shadow-*` class / generated `shadow.css`, and FAILS (RED-proved) when an ad-hoc `box-shadow: 0 1px 2px …` literal is injected into a component CSS file.
- [ ] Given the provisional external base, When the test suite documents it, Then `docs/external-deps/lab-colors.md` records the absolute-alpha/absolute-base dependency as an OPEN external blocker (owned by lab-colors JND calibration), so the order-only test's deliberate silence on magnitudes is documented, not a gap.
