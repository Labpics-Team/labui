## Notes

### Architecture (SOLID/DDD/Clean — layers + dependency direction)
- **Domain** (`packages/shadow/src/domain/`): pure value objects + laws — `SHADOW_SLOTS`/`SLOT_ALPHA` (the four-ply law), `ELEVATION_*` (the role ladder), `composePly`/`composeElevation` (geometry). No I/O, no colour resolution.
- **Generation** (`generate-css.ts`): pure function `config → CSS string`. Deterministic, idempotent. Depends inward on domain only.
- **Contract seam** (the `--lab-shadow-alpha-*` / `--lab-surface-shadow-tint` CSS custom properties): the ONLY coupling to `@labpics/colors`. Dependency direction points OUT through named CSS vars — the shadow package never imports colour code (DIP: depend on the contract abstraction, not the engine).
- **Consumer** (`apps/docs` demo, downstream components): read `--lab-elevation-*` / `.lab-shadow-*`, never author box-shadow literals. The consumed-not-reinvented guard enforces this direction.
- **CLASS closed**: half-applied rename → red build + unverified contract; and silent re-invention of elevation as ad-hoc literals. Closed by landing-as-one-unit + order-only contract test + consumed-not-reinvented guard.

Judges = **verification-runner** (RED-proof on the two new guards) + **arch-reviewer** (layer direction) + **qa-tester** (e2e).
